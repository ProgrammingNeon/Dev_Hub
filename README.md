# DEV•HUB 🚀

**DEV•HUB** — це сучасна Full-Stack веб-платформа для автоматизації деплою та хостингу студентських веб-портфоліо. Користувачі можуть завантажувати свої проєкти у вигляді ZIP-архівів, після чого система автоматично розпаковує їх, аналізує структуру, знаходить точку входу та публікує сайт у загальному каталозі.

Платформа розроблена в першу чергу для згуртування розробників усередині навчальної групи, створення єдиного реєстру талантів та демонстрації їхніх робіт.

---

## ✨ Ключовий функціонал та особливості

### 🛠️ Стек та Архітектура
* **Backend:** FastAPI (Python 3.10+) — високопродуктивний асинхронний фреймворк.
* **Database:** PostgreSQL — збереження профілів студентів та метаданих проєктів, зв'язки «Один до багатьох» (One-to-Many).
* **ORM:** SQLAlchemy (Session Management).
* **Frontend:** Чистий семантичний HTML5, сучасний CSS3 (Luxury Dark Glassmorphic дизайн) та асинхронний JavaScript (Fetch API).

### 🛡️ Інженерні рішення та безпека деплою
* **Розумний рушій автопошуку `index.html`:** Користувачеві не потрібно турбуватися про внутрішню структуру ZIP-архіву. Бекенд за допомогою `os.walk` сканує дерево папок вглиб, знаходить точку входу та динамічно генерує правильний веб-шлях.
* **Захист від ZIP-бомб:** Перед розпакуванням система аналізує метадані архіву через `infolist()` та блокує деплой, якщо сумарна вага розпакованих файлів перевищує ліміт (50 МБ).
* **Фільтрація файлів (White-list):** Дозволено розпакування лише безпечних frontend-компонентів (`.html`, `.css`, `.js`, зображення та шрифти). Завантаження шкідливих скриптів (`.py`, `.php`, `.exe`) повністю блокується на рівні валідатора.
* **Принцип атомарності ("Все або нічого"):** Якщо в процесі деплою або валідації виникає помилка, створена директорія повністю підчищається за допомогою `shutil.rmtree`, не залишаючи сміття на диску сервера.
* **Інтерактивна форма з Debounce:** На фронтенді реалізована перевірка імені студента «на льоту». Якщо студент вже існує в базі, поля контактів заповнюються автоматично, а система попереджає, якщо нові дані відрізняються від попередніх.
* **Динамічний стек (Hard Skills):** На сторінці профілю студента автоматично збираються та виводяться унікальні плашки технологій з усіх його завантажених проєктів без дублювання.

## 📂 Структура проєкту

```text
├── database.py          # Ініціалізація та налаштування підключення до БД
├── main.py              # Головний файл додатка, API ендпоінти та бізнес-логіка
├── models.py            # Декларативні моделі SQLAlchemy (Student, Project)
├── templates/           # Jinja2 HTML-шаблони
│   ├── index.html       # Головна сторінка зі статистикою та останніми деплоями
│   ├── portfolios.html  # Каталог усіх завантажених робіт
│   ├── upload.html      # Інтерактивна форма завантаження портфоліо
│   └── profile.html     # Персональний профіль розробника з його склеєним стеком
└── static/              # Статичні файли додатка
    ├── css/
    │   └── style.css    # Глобальні стилі додатку (Dark Glassmorphism)
    ├── script.js        # Фронтенд-логіка (асинхронні запити, debounce, автопідстановка)
    └── uploaded_sites/  # Директорія, де ізольовано зберігаються розпаковані сайти

## 🚀 Локальне розгортання (Local Setup)

### 1. Клонування репозиторію
```bash
git clone https://github.com/your-username/dev-hub.git
cd dev-hub
```

### 2. Налаштування віртуального оточення та залежностей
```bash
python -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Конфігурація бази даних
Переконайся, що у тебе запущений PostgreSQL сервер. У файлі `database.py` вкажи свій рядок підключення:

```python
SQLALCHEMY_DATABASE_URL = "postgresql://username:password@localhost:5432/devhub_db"
```

### 4. Запуск сервера
```bash
uvicorn main:app --reload
```
Додаток буде доступний за адресою: http://127.0.0.1:8000
